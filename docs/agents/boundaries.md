# Always / Ask first / Never

모든 에이전트와 팀원이 공유하는 작업 경계다.

## Always (항상 해도 됨)

- 로컬 파일 읽기·탐색, 린트·포맷 검사 실행
- `feature/*`, `hotfix/*` 브랜치 생성
- 테스트 작성 및 실행
- `docs/` 문서 읽기
- 이미 승인되어 프로젝트 설정에 선언된 의존성 설치

## Ask first (먼저 확인)

- **새 의존성 추가** — 환경·패키지 관리 도구, 용도, 라이선스를 확인한 뒤 진행
- **데이터 스키마·수집 방식 변경** — 영향 범위와 함께 승인 필요
- **브랜치 머지** — PR을 통해서만. 직접 머지 금지
- **환경변수 추가** — 어느 환경에 추가할지 확인
- **외부 API 연동 추가** — 비용·인증 방식·키 관리 확인
- **대규모 리팩터링** — 범위·영향도 사전 논의

## Never (절대 금지)

- `main`·`develop` 브랜치에 직접 push (`docs/conventions/git.md`의 승인된 최초
  `develop` 생성 1회는 제외)
- `.env`·비밀키·자격증명 파일 커밋
- API 키·비밀번호 코드 하드코딩
- `--no-verify`로 훅 우회
- `git reset --hard`, `git push --force` (명시적 요청 없이)
- 대용량 원본 데이터를 저장소에 커밋
- 비밀번호·PII를 로그로 출력
- 검증 증거 없는 완료 보고
- 사용자 승인 없는 커밋·push
