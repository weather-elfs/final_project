# AI 에이전트 표준 작업 절차

팀원이 어떤 에이전트(Antigravity, Codex, Claude Code)를 쓰든 아래 절차를 동일하게
따른다.

## 시작 전 체크리스트

1. `AGENTS.md`를 읽는다 — 프로젝트 개요, 규칙, Critical Triggers 파악.
2. 처음 사용하는 도구이거나 지침 로딩 방식이 바뀌었다면
   `docs/agents/tool-compatibility.md`의 확인 절차를 실행한다.
3. 작업과 관련된 컨벤션 문서를 읽는다 (`docs/conventions/`).
4. 현재 브랜치를 확인한다: `git branch --show-current`
5. 현재 개발 단계를 확인한다.
   - 초기 문서 기준선을 원격 `develop`에 최초 게시하기 전: `develop`에서 작업한다.
   - 기준선 게시 이후의 데이터 출처 조사·스키마·대시보드 설계·기능 코드 등 실제
     프로젝트 작업: 최신 `develop`에서 `feature/*`를 분기한다.
   - 운영 긴급 수정: `main`에서 `hotfix/*`를 분기한다.
   - 저장소 변경이나 프로젝트 산출물이 없는 단순 상태 점검·답변이거나 이미 적절한
     작업 브랜치라면 새 브랜치를 만들지 않는다. 결과를 `docs/research/` 등에 남기는
     데이터 출처 조사는 프로젝트 작업이므로 기준선 게시 후 `feature/*`를 사용한다.

## 작업 절차

### 1. 변경 전

- 관련 기존 코드를 먼저 파악한다.
- 데이터 수집·전처리 변경이면 `docs/conventions/data.md`를 확인한다.
- 대시보드 화면 변경이면 `docs/conventions/dashboard.md`(작성 예정)를 확인한다.

### 2. 구현

- 요청 범위에서 가장 작은 변경을 우선한다. 관련 없는 코드를 임의로 고치지 않는다.
- PEP8·isort 규칙을 지킨다 (`docs/conventions/general.md`).

### 3. 검증

- 커밋 전 `docs/conventions/general.md`의 **에이전트 자체 점검** 목록을 스스로 확인한다
  (버그·가독성·안전). 자체 점검은 자동 린터와 테스트를 대체하지 않는다.

```bash
pre-commit run --all-files   # Black·isort·형식 검사
pytest                       # 테스트 (도입 시)
```

- 설치되고 설정된 검증 도구만 실행한다. 도구가 없으면 임의로 설치하지 않고 누락된
  도구, 실행하지 못한 검사, 남은 위험을 완료 보고에 기록한다.
- 실제로 실행한 명령과 그 출력으로 검증한다.

### 4. 커밋

- Conventional Commits 형식, 한글 포함, 이모지 금지.
- 관련 파일만 스테이징한다 (`git add <파일>`, `git add .` 지양).
- 커밋·push는 **사용자 승인 후**에만 한다.

## 완료 보고 규칙

- 검증 명령의 출력 결과를 첨부한다.
- 추정·가정으로 완료를 보고하지 않는다.
- 실행하지 못한 검증이 있으면 무엇을·왜 못 했고 남은 위험이 무엇인지 밝힌다.

```
# Good
pytest 실행 결과:
3 passed in 0.42s

# Bad
"테스트가 통과할 것으로 예상됩니다"
```
