# 데이터 컨벤션

이 문서는 데이터 출처가 확정되기 전에도 지켜야 하는 기본 규칙을 정의한다.
출처별 필드와 품질 기준은 데이터 출처를 검증한 뒤 이 문서와 `docs/research/`에 추가한다.

## 구현 전 확인 사항

데이터 수집·전처리 코드를 작성하기 전에 다음 항목을 확인하고 기록한다.

- 제공 기관과 공식 데이터셋 이름
- 이용 약관·라이선스·재배포 가능 여부
- 공개·제한·민감 여부와 외부 AI 서비스 입력 가능 여부
- API 인증 방식, 호출 제한, 비용
- 필드 정의, 단위, 시간대, 좌표계, 결측값 표기

확인되지 않은 항목은 추정값으로 채우지 않는다. 필요한 근거가 없으면 구현을 보류하고
공식 제공 기관의 문서나 담당자 확인 경로를 남긴다.

## 데이터 계층

```text
data/raw/         원본 응답 또는 원본 파일, 수정 금지
data/interim/     정규화·정제 중간 결과, 원본에서 재생성 가능
data/processed/   분석·대시보드 입력용 결과, 파이프라인으로 재생성 가능
tests/fixtures/   익명화하고 크기를 줄인 자동 테스트 전용 샘플
```

- `data/` 아래 생성 데이터는 Git에 커밋하지 않는다.
- 원본을 직접 수정하지 않고 모든 변환은 새 계층에 기록한다.
- 테스트 fixture만 예외로 커밋할 수 있으며 비밀정보·개인정보·제한 데이터가 없어야 한다.
- 분석 결과가 원본에서 재현되도록 실행 코드와 설정을 함께 관리한다.

## 스키마와 단위

- 수집기 출력에는 관측 시각, 관측 지점 식별자, 위치, 변수명, 값, 단위, 품질 상태를
  표현할 수 있어야 한다.
- 저장 시각은 시간대 정보가 있는 UTC로 정규화하고 원본 시간대 정보가 있으면 보존한다.
- 대시보드 표시 시간대는 요구사항 확정 후 별도로 정한다.
- 단위 변환은 명시적인 함수에서 수행하며 입력 단위와 출력 단위를 테스트한다.
- 결측값을 임의의 0이나 평균값으로 바꾸지 않는다. 처리 방법과 근거를 코드·메타데이터에
  기록한다.
- 스키마 변경은 영향 범위와 마이그레이션 방법을 제시하고 사용자 승인을 받은 뒤 진행한다.

## 출처와 계보

각 수집 결과에서 다음 정보를 추적할 수 있어야 한다.

- 데이터 출처와 데이터셋 식별자
- 수집 시각과 대상 기간
- 수집기 또는 파이프라인 버전
- 적용한 전처리 단계와 설정

파일명만으로 계보를 추정하지 않는다. 저장 형식이 확정되면 위 항목을 담을 메타데이터
형식도 함께 확정한다.

## 보안과 외부 공유

- 공개 여부를 확인하지 못한 국방 관련 데이터는 외부 AI 서비스, 공개 저장소, 개인
  클라우드에 업로드하지 않는다.
- API 키와 자격증명은 환경변수로 전달하고 데이터 파일이나 노트북 출력에 남기지 않는다.
- 위치 정보나 식별자가 민감할 수 있으면 익명화·집계 기준을 승인받기 전까지 공유하지 않는다.
- 로그에는 자격증명, 개인정보, 원본 응답 전체를 출력하지 않는다.

## 검증

- 수집 단계에서 필수 필드, 타입, 허용 범위, 단위를 검증한다.
- 전처리 테스트는 정상값뿐 아니라 결측값, 범위 밖 값, 중복 관측, 시간대 경계를 포함한다.
- 외부 API를 사용하는 테스트는 고정 fixture로 재현 가능하게 만들고 실제 API 호출은
  통합 테스트로 분리한다.
